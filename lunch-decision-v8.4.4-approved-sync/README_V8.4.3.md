# V8.4.3 — 여행코스 화면 및 지도 길찾기 수정

## 바뀐 내용
1. 화면 깨짐 해결: 오래된 `.trip-day` CSS와 충돌하지 않도록 `itinerary-*` 전용 컴포넌트로 출력합니다. V8.4.3 파일을 새 폴더에 풀고, CSS/JS 파일 주소에 버전 쿼리 `?v=843`을 넣어 캐시된 이전 버전이 사용되지 않도록 했습니다.
2. 관리자와 길찾기 분리: 지도 검색·길찾기는 Google 지도 링크(`https://www.google.com/maps/dir/?api=1...`)로 처리합니다. 관리자 로그인, 장소 저장, API 키가 필요하지 않습니다.
3. 오늘의 점심: 화면에 추천된 음식점 이름/주소(확인된 실좌표가 있으면 좌표)를 바로 목적지로 사용합니다.
4. 직접 길찾기: 사용자가 직접 입력한 장소명이나 주소를 Google 지도로 연결합니다. 사용자가 직접 위도·경도를 입력할 필요가 없습니다.
5. 여행 1~3일 및 각 6개 방문 단계: 각 장소마다 직접 클릭할 수 있는 길찾기 링크를 생성합니다. 출발지 모드를 바꾸면 링크도 즉시 변경됩니다.

### 가상 테스트 장소 주의
시스템의 56개 가상 테스트 장소는 **실재하는 시설이 아닙니다**. 주소/좌표를 꾸며서 길찾기 목적지로 사용하지 않습니다. '지역 길찾기'는 해당 행정구역까지 안내할 뿐, 가상 샘플 시설에 도착하는 길을 제공하지 않습니다. 특정한 실매장 경로를 원하면 실제 장소명 또는 주소를 '직접 길찾기'에 입력하세요.

## 업데이트 절차 (Windows PowerShell)
- 기존 V8.4.2 서버 종료: PowerShell에서 `Ctrl + C`.
- V8.4.3 ZIP을 **별도 폴더**에 압축 해제.
- 기존 V8.4.2의 `.env`만 새 폴더로 복사. 절대로 DB 생성 SQL이나 데이터 이관을 다시 실행할 필요 없음.
- 새 프로젝트 폴더에서:

```powershell
npm install
npm run test:ui
npm run test:map
npm start
```

- 브라우저에서 `http://localhost:3100` 접속.
- 이전 화면이 남으면 `Ctrl + Shift + R` 강력 새로고침.

## 빠른 시험
1. 점심 결정 후 '지도에서 보기' → 이름·주소로 검색하는지 확인.
2. 점심 결정 후 '선택된 음식점 길찾기' → Google 지도 `/maps/dir/`가 열리는지 확인.
3. 별도 장소명이나 도로명주소를 입력하고 '바로 길찾기' → 관리자 등록 없이 지도 연결.
4. 여행 2일 또는 3일 선택 → 화면의 일정이 가로 6행씩 표시되는지 확인.
5. 각 행 '길찾기' 링크 → 현재 위치 또는 선택한 지역에서 출발하는지 확인.
6. 임시 가상 샘플은 '지역 길찾기'로 표시되는지 확인.

## 점검 결과와 제한
- Node.js 검사 및 자동화된 URL·데이터·DOM 코드 테스트 통과.
- 이 환경에서는 브라우저의 외부 및 로컬 페이지 탐색이 차단되어 실제 Google 지도 페이지와 사용자 PC의 브라우저에서 최종 클릭을 확인할 수는 없습니다.
- OSRM 이동시간은 실제 좌표가 있는 장소에 한해 별도로 계산합니다. 지도 길찾기 링크는 OSRM이나 Google API 키를 요구하지 않습니다.
