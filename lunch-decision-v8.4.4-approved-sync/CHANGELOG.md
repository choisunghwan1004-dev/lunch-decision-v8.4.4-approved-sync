# 변경 이력

이 문서에는 변경 목적과 실제 검증 결과를 기록한다. 상세 실행 방법은 [README](README.md), 코딩 작업 절차는 [AGENTS.md](AGENTS.md)를 따른다.

## 2026-10-20

### 원문 비교·검증 저장 간소화와 상태 변경 제거

- 첨부 오류는 이전 승인 API의 필수 의견 3자·최종 체크 4개 누락으로 입력 단계에서 거절된 것이었다. 기본 화면의 해당 필수 항목·문장별 반복 체크·별도 승인/게시 버튼을 제거했다.
- 원문 근거와 기사 본문을 나란히 표시하고 확인 체크 1개·선택 메모·검증 완료·저장으로 처리한다. Fact 검증·기사 수정 메모도 선택으로 바꿨으며 Fact 목록의 상태 변경 항목을 제거했다.
- 새 `verify-and-save` API는 사람의 전체 원문 대조 기록, 문장 근거 판정, 승인 이력, 공개 상태를 같은 MySQL 트랜잭션에 저장한다. 실패 시 전체 취소하며 중복 요청은 현재 공개본을 재사용한다. 근거 변경·시연·불일치·오래된 기사 해시는 계속 차단한다. 기존 상세 API·DB 자료·감사 이력은 보존한다.
- 사용자 화면은 **지역 소식**과 새로고침만 표시하고 검증 저장한 최신 기사 최대 30건을 점심·여행 선택과 무관하게 보여준다. 공개 중단과 열린 메인 갱신을 유지한다. SQL 추가 적용은 없다.
- 검증: 실제 MySQL 8.0.36에서 뉴스 테스트 **85개**, Node 테스트 **36개** 통과. Chromium에서 체크 누락 한글 안내, 체크 1개, 빈 메모 저장, 상태 변경 미노출, 저장 즉시 열린 지역 소식 반영, 점심 지역 변경에도 유지, 공개 중단·재검증 저장·일본·모바일을 확인했다. 간편 절차의 실제 실행 GIF를 갱신했다. AI 응답은 테스트 대역이며 유료 OpenAI·노션·사용자 운영 DB·Windows BAT는 실행하지 않았다.


### 저장·승인한 뉴스의 메인 미노출 점검과 갱신 수정

- 첨부된 빈 목록 화면만으로 사용자 DB의 저장 실패를 확정할 수 없음을 구분했다. 게시 전에 열어 둔 메인이 관리자 게시 후 재조회하지 않는 로직을 수정했다.
- 게시·중단 시 같은 브라우저의 다른 탭에 시각 알림을 보내 공개 목록을 재조회한다. 화면 복귀 시 재조회와 명시적 새로고침을 추가하고, 현재 조회 지역·전체 지역 조회를 제공했다. 기존 점심·여행 지역 선택은 유지했다.
- 관리자에 출처·Fact·검증·기사·승인·게시 저장 수와 다음 단계를 표시했다. 최종 승인 직후 기사 창을 유지해 별도 승인본 게시를 안내한다. 미승인·시연 자료의 공개 제한은 유지한다.
- `docs/NEWS_PUBLICATION.md`에 저장 단계별 미노출 원인과 확인 순서를 추가하고 README 자동 요약·체크리스트·실행 GIF를 갱신했다. 승인·게시 시연은 **모의 AI 응답의 격리 테스트**임을 이미지와 설명에 표시했다.
- 검증: Node 36개, 실제 MySQL의 뉴스 업무 테스트 20개 통과. 실제 Node/FastAPI/Chromium에서 승인만으로 미노출, 게시 후 이미 열린 메인의 자동 반영, 다른 지역과 전체 지역 구별, 게시 중단 후 목록 제거, 재승인·게시, 일본·모바일 흐름을 확인했다. Windows BAT·실제 OpenAI·노션·사용자 운영 DB는 실행하지 않았다. 추가 SQL은 없다.

### 지역 뉴스 README 자동 갱신과 실제 실행 GIF

- 코드의 뉴스 버전·모델·16시 예약·API, SQL 테이블, 자료 파일의 Fact·출처 수를 읽어 README의 지정 구역만 갱신하는 생성기를 추가했다. `npm run docs:news`, `docs:news:check`, `test:docs`와 `check`의 사전 갱신을 제공한다.
- 저장소 루트의 `Regional news README sync` GitHub Actions workflow를 추가했다. `main`의 관련 변경에서 검사 후 차이가 있는 README 한 파일만 자동 커밋하도록 구성했다. 수동 편집 영역은 보존하며 강제 푸시·비밀 설정 읽기·DB·외부 API 호출을 하지 않는다.
- 실제 UI에서 한국·일본 점심 추천(5단계), 종로 2일 여행(4단계·12개 장소 단계), 종로 CSV와 출처 입력 화면(7단계)을 캡처해 GIF 3개를 추가했다. 녹화 기록에서 이미지·환경·검증 범위를 README에 반영한다.
- 출처 등록 항목별 실제 입력 예시, 한국 시간→UTC 변환, 원문 구절과 이용 조건 확인 기록을 추가했다. URL 자동 수집과 16시 초안 예약을 구별하며 CSV/JSON 가져오기만으로 Fact 검증·AI 생성·게시가 되지 않는다고 안내했다.
- 검증: Node 테스트 **36개(문서 생성기 5개 포함)**, 코드 구문 검사 통과. 실제 MySQL 8.0.36·FastAPI·Chromium 134에서 한국/일본 추천, 여행 2일·12단계, 종로 출처 3건·Fact 후보 8건·근거 연결 8건을 확인했다. 초안·게시·AI 사용 기록 0건, 브라우저 스크립트 오류 0건. GIF의 주요 프레임·한글·UTC·검증 대기 표시를 확인했다.
- 미실행: 실제 OpenAI·노션 호출, Windows BAT/녹화 재현 명령 직접 실행. 운영 PC의 DB·설정은 이번 녹화에 사용하지 않았다. 이전의 GIF 대기 기록은 당시 이력으로 보존한다.

### 종로 행사 실제 CSV·JSON 자료 추가

- 공개 행사 일정과 관련 기사·주최자 보도자료를 확인해 종로 행사 4건의 일정·장소·내용을 Fact 후보 8건으로 정리했다. 기사 전문이나 사진은 포함하지 않았다.
- `data/news/jongno_20261020`에 기존 가져오기 규격의 CSV·JSON과 출처·게시 시각·공식 교차 확인·가져오기 안내를 추가했다. `is_demo=false`이며 가져오기 후 사람의 검증이 필요하다.
- 기존 화면·API·DB 스키마와 예약 작업은 변경하지 않았다. README에 실제 파일과 확인 항목을 연결했다.
- 검증: 두 형식의 파서 결과 일치, 격리된 SQLite/FastAPI에서 형식별 출처 3건·Fact 8건·근거 연결 8건 및 전원 후보 상태, 중복 재가져오기 409와 무변경, 기존 가져오기 테스트 11개. 실제 MySQL·브라우저·OpenAI·노션·Windows 실행은 이번 작업에서 다시 수행하지 않았다.

- 검증: 기존 README·변경 이력 보존, 새 상대 링크·앵커·접기 태그·코드 블록·이미지 대기 처리, 변경 파일 차이·공백을 검사했다. 공식 배포·사용법과 GitHub 문서를 확인했다.
- 미실행: 실제 Windows 녹화와 GIF 재생 검증. 애플리케이션 변경이 없어 앱·DB·외부 API 테스트는 다시 실행하지 않았다.
