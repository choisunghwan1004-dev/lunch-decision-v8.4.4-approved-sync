# 더블클릭 한 번으로 점심 여행 뉴스 실행하기

`package.json`이 보이는 폴더의 **00_한번에_실행.bat**을 더블클릭한다. 실행 환경을 준비하고 뉴스 FastAPI·점심/여행 Node 서버와 DB 연결을 확인한 뒤 **메인·관리자 화면을 자동으로 연다.** 같은 실행창에서 두 서버를 관리한다.

## 기존 프로그램에 적용

1. 기존 Node·FastAPI 서버 창에서 각각 `Ctrl+C`를 눌러 종료한다. 이전 09번으로 실행한 서버는 새 실행기의 식별 정보가 없어 최초 한 번 종료해야 한다.
2. ZIP을 다른 임시 폴더에 **모두 압축 풀기** 한다. ZIP 안에서 바로 실행하지 않는다.
3. 풀린 `lunch-news-oneclick` **안의 파일과 폴더**를 기존 `package.json`이 보이는 폴더에 복사하고 **대상 파일 바꾸기**를 선택한다. 폴더 자체를 기존 폴더 안에 한 겹 더 넣거나 “두 파일 모두 유지”를 선택하지 않는다.
4. 기존 `.env`·`.venv`·`node_modules`는 유지한다. 새 ZIP에는 실제 `.env`가 없으며 이번 변경은 **SQL 추가 적용·DB 초기화가 없다.**
5. 기존 폴더에 새로 생긴 **00_한번에_실행.bat**을 더블클릭한다. 이후부터는 이 파일 하나로 실행한다.

정상 실행 시 콘솔의 **준비 완료**와 함께 기본 주소 `http://127.0.0.1:3100/`·`http://127.0.0.1:3100/admin`이 열린다. `.env`의 `PORT`를 바꿨으면 변경한 주소로 열린다. 관리자 계정은 기존 `.env` 설정을 사용한다.

## 실행기가 자동 처리하는 일

| 순서 | 처리 |
| --- | --- |
| 1 | Node.js 버전·프로젝트 위치·중복 실행창 확인 |
| 2 | 필요한 Node 패키지가 없으면 `npm ci` 실행 |
| 3 | 설치된 Python 3.11 이상을 `python` 또는 `py`로 찾아 `.venv` 준비. 필요한 버전의 Python 패키지가 없으면 설치 |
| 4 | 기존 설정 준비 명령의 `--init-env-only`로 뉴스 내부 토큰·연결값 준비. DB SQL은 실행하지 않음 |
| 5 | `PORT`·`NEWS_SERVICE_URL`을 반영해 서버 기동. 같은 폴더·같은 버전·정상 DB의 서버만 재사용 |
| 6 | 뉴스 DB 상태, Node DB 연결, Node→FastAPI 연결과 공개 피드 조회 확인 |
| 7 | 준비된 메인·관리자 화면을 기본 브라우저로 열기 |

처음 패키지를 설치할 때는 인터넷 연결과 시간이 필요하다. 이미 준비되어 있으면 설치를 반복하지 않는다. OpenAI 키가 없어도 화면·사람 검수는 사용할 수 있다. 유료 AI 생성·자동 검수는 관리자에서 버튼을 눌렀을 때 실행하며, 이 시작 파일은 유료 호출·노션 쓰기·예약 등록을 실행하지 않는다.

## 처음 설치하는 PC

**Node.js·Python·MySQL 프로그램과 실제 DB 설정은 한 번 준비해야 한다.** 이 BAT는 MySQL 서버 설치나 비밀번호 입력을 대신하는 휴대용 EXE가 아니다.

- Node.js 18.18 이상, Python 3.11 이상, MySQL 8.x를 설치한다. 기존 프로젝트에서 이미 사용 중이면 다시 설치하지 않는다.
- `.env`가 없으면 실행기가 예제 파일을 만들고 Windows 메모장으로 연다. 실제 DB 비밀번호·관리자 암호·세션 설정을 한 번 입력하고 저장한다. 기존 설정 파일을 덮어쓰지 않는다.
- 신규 DB는 [SQL 처리 순서](README.md#7-sql-파일-처리-방법)를 따른다. 기존 뉴스 테이블이 있으면 백업 후 업그레이드 여부를 판단한다. 기존 설치에 신규용 SQL을 반복 적용하지 않는다.
- MySQL 서비스를 실행한 후 00번을 다시 더블클릭한다. Python을 못 찾으면 설치 시 PATH 옵션을 확인하고 실행창을 새로 연다.

## 종료와 오류 확인

실행창을 열어 두고 사용한다. 정상 종료는 실행창에 **Q 입력 → Enter** 또는 **Ctrl+C**다. 새 실행기가 시작한 서버를 함께 종료한다. 이미 실행 중이어서 재사용한 서버는 원래 서버 창에서 관리한다.

| 표시 | 조치 |
| --- | --- |
| 다른 통합 실행창에서 이미 실행/준비 중 | 이미 열려 있는 00번 창과 브라우저 확인. 두 번째 클릭은 서버를 새로 만들지 않음 |
| 포트에 다른 폴더 또는 이전 서버 실행 중 | 해당 서버 창에서 Ctrl+C. 이전 09번 서버도 최초 한 번 종료 후 다시 실행. 다른 프로세스를 무조건 강제 종료하지 않음 |
| MySQL·뉴스 DB 확인 실패 | Windows 서비스에서 MySQL 실행 여부, `.env`의 DB 설정·테이블 설치 확인. [DB·뉴스 복구](README_NEWS_RECOVERY.md) 참고 |
| 패키지 설치 실패 | 인터넷·Python 버전 확인. 오류 안내를 수정하고 00번 재실행. 실제 키를 로그·채팅에 붙이지 않음 |
| 브라우저가 열리지 않음 | 콘솔의 준비 완료 주소를 직접 열기 |
| 기사 화면이 예전 모습 | 파일 바꾸기·기존 서버 종료 확인, 브라우저 Ctrl+F5. 필요하면 19번으로 화면 버전 진단 |

`NEWS_SERVICE_URL`은 `http://127.0.0.1:8001` 같은 로컬 주소여야 하며 웹 `PORT`와 다른 포트를 사용한다. `localhost`도 실행 중에는 IPv4 루프백으로 통일한다. 포트 자동 변경으로 다른 주소의 앱을 띄우지 않는다.

## 개발 환경과 확인 항목

실행 진입점은 BAT → `scripts/start-all.js`다. 서버 준비 응답에는 실제 폴더 경로 대신 SHA-256 지문과 `oneclick-v1` 식별자를 추가했다. 기존 점심·여행·뉴스 화면·업무 API·SQL은 그대로 사용한다. 임시 실행 잠금은 Git에서 제외한 `.run/start-all.lock`에 저장한다.

```powershell
npm run test:launcher
npm run test:ui
npm run check
npm run docs:news:check
# Python 개발용 의존성 설치 후
.\.venv\Scripts\python.exe -m pytest tests/news -q
```

확인할 동작: 두 서버 준비 후 브라우저 열기, 설정 포트 반영, 중복 클릭 차단, 정상 서버 재사용, 다른 폴더 서버 보존, DB 실패 시 성공 표시 금지·새 서버 정리, 한 서버 종료 시 나머지 정리, 종료 후 재실행.

실행기 검사는 Linux에서 실제 HTTP 자식 프로세스와 **모의 준비 응답**을 사용한다. 실제 Windows BAT·기본 브라우저 자동 열기와 사용자 PC MySQL은 별도로 확인해야 한다. 이번 결과는 [검증 보고서](NEWS_TEST_REPORT.md)에 기록한다. 이전 MySQL·실행 GIF의 녹화 날짜는 유지한다.

실행 방식 참고: [Node.js 공식 child_process 문서](https://nodejs.org/api/child_process.html#spawning-bat-and-cmd-files-on-windows). Windows BAT·npm 실행은 `cmd.exe`를 거치고 Python·Node 서버는 인자 배열로 직접 실행한다.
