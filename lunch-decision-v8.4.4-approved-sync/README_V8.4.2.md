# V8.4.2 — 여행 일수·길찾기·샘플 데이터 보완

이 버전은 정상 실행되던 V8.4.1의 **기존 `lunch_decision_v83` DB를 그대로 사용**합니다. 회원, 음식점, 방문 기록을 삭제하지 않습니다.

## 수정 사항
1. 여행 **1일·2일·3일**을 선택하면 각 날짜별 6단계(관광·점심·카페·관광·저녁·숙박)를 생성. 장소 수가 충분하면 중복 회피.
2. 여행일수를 바꾸면 이전에 여행코스를 생성한 경우 자동 재생성. 다시 `관광코스 자동 결정`을 눌러도 됨.
3. 여행 장소명 텍스트가 한 글자씩 세로로 깨지는 CSS 문제 수정.
4. 점심 추천의 `지도에서 보기`, `길찾기`, 여행 각 단계의 `길찾기`: **주소나 이름**으로 Google Maps를 열며 수동 좌표 입력 없음.
5. 길찾기 출발점을 `현재 위치`(Google 지도에서 확인) 또는 `선택 지역` 중 선택.
6. **종로구 한 구역**에 가상 테스트 장소를 음식점 14, 카페 14, 숙박 14, 관광지 14, 합계 **56곳** 추가.
7. 관리자 대시보드의 장소별 수량 표기 개선.
8. `npm run verify:travel`: 실제 DB에서 카테고리별 10개 이상과 3일 18단계 FK 연결 확인.
9. `npm run test:api`: 1/2/3일 API 응답, 6/12/18 방문 단계 검사.

## ★ 가장 간단한 Windows 실행 순서

1. 기존 서버 창에서 Ctrl+C로 종료. DB를 삭제하거나 SQL 초기화하지 마세요.
2. 새 ZIP을 새 폴더에 풉니다. 기존 `.env`를 **새 폴더의 루트**에 복사합니다.
3. 새 폴더에서 PowerShell을 열고 아래 명령을 순서대로 실행합니다.

```powershell
npm install
npm run backup
npm run seed:travel
npm run verify:travel
npm run test:ui
npm run test:api
npm start
```

`npm run seed:travel`에서 `종로구 샘플 상권 없음`이 나오면 먼저 다음 명령을 **한 번** 실행합니다.

```powershell
npm run seed:demo
```

이 명령은 먼저 원본 6개 지역 경로를 준비하고 마지막에 56개 샘플을 등록합니다. 같은 샘플 데이터는 중복 등록하지 않습니다.

`npm run test:api`는 서버가 안 떠 있으면 임시 서버를 실행합니다. 다른 포트의 앱이 작동 중이면 `.env`의 `PORT`를 확인하세요.

4. 웹: http://localhost:3100 (또는 `.env`의 PORT). 여행 도시 **종로구** 선택 → 여행 일수 1, 2, 3일 선택 → `관광코스 자동 결정`.
5. 2일은 2개 일정 카드, 12개 단계. 3일은 3개 일정 카드, 18개 단계가 나와야 합니다.

## 샘플 지도·이동시간의 한계 (중요)

- 새로 입력되는 56곳은 **실제 매장/호텔이 아닌 가상 테스트 데이터**입니다. 이름·주소·영업시간·가격을 실재하는 것처럼 안내하지 않습니다.
- 가상 장소에 좌표를 임의로 넣지 않았습니다. 지도 버튼은 **선택한 지역 중심**을 찾을 뿐 개별 매장 위치까지 안내하지 않습니다.
- 따라서 가상 장소끼리의 이동시간은 `미확인`입니다. `0분/0km`처럼 표시하지 않습니다.
- **실제** 장소에 정확한 주소나 좌표가 등록되어 있으면 지도는 해당 주소/좌표로 안내하고, 정확한 좌표가 *양쪽 모두* 있는 구간에서는 OSRM 경로를 조회합니다.
- 이 버전은 날짜별 분산과 연결 확인용 **테스트 엔진**이며, 현실의 가격/영업시간/실시간 교통/날씨 기반 최적화를 보장하는 완성형 여행 예약기가 아닙니다.
