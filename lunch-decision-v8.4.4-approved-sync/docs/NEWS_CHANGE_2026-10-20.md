## 1. 기능정의서

| 기능 | 변경 전 | 추가·변경 후 | 확인 기준 |
| --- | --- | --- | --- |
| Fact 검증·열람 | verified로 저장해도 최종 기사가 없으면 메인에 나오지 않음 | 운영용 주제의 검증 Fact를 주제별 한 소식으로 표시 | 기사·AI 사용 기록 없이 내용·원문 출처 조회 |
| 원문 비교·기사 저장 | 문장별 입력, 확인 4개, 승인·게시를 따로 처리 | 원문/기사 비교 → 확인 1개 → 검증 완료·저장, 메모 선택 | 승인·공개가 한 트랜잭션으로 저장, 실패 시 전체 취소 |
| 기사 교체 | 기사 전용 목록 | 기사 최종 저장 시 같은 주제의 Fact 카드를 기사로 교체 | 같은 주제 한 카드, 미검토 AI 본문 제외 |
| 공개 중단 | 기사 공개 해제 | 중단한 주제가 Fact 카드로 자동 재등장하지 않도록 공개 이력 확인 | 기사 재검증·저장으로만 재공개 |
| 변경 후 갱신 | 게시·중단 알림 중심 | Fact 검증·수정·삭제와 기사 저장 알림, 화면 복귀·새로고침·보이는 화면 30초 재조회 | 먼저 열어 둔 메인에도 변경 반영 |
| 기존 점심·여행 | 한국·일본 지역과 장소·여행 일정 | 기존 기능 유지, 뉴스만 지역 선택과 독립 | 한국/일본 선택·일정·모바일 검사 통과 |

**공개 기준:** 운영용 주제, verified Fact, 검증자·시각·메모, 완전한 원자료·이용 조건, 출처 내용 지문 일치가 필요하다. 후보·시연 자료·불완전 근거는 제외한다. 기사는 기존 제목/본문 근거·승인 검사를 통과해야 한다. 사람이 사실을 원문과 대조하며 해시나 AI가 진위를 증명하는 것은 아니다.

## 3. DB 설계

**DDL·테이블·컬럼·PK/FK는 변경하지 않았다.** 기존 데이터를 읽는 조회 조건과 공개 응답을 보강했다. 새 뉴스 테이블을 만들거나 운영 자료를 다시 입력할 필요가 없다.

| 기존 테이블 | 관계/필드 | 이번 조회에서의 사용 |
| --- | --- | --- |
| districts | `id` PK | 한국·일본 기존 지역 재사용 |
| news_topics | `id` PK, `district_id` FK, `is_demo` | 운영 주제·지역·제목과 Fact 묶음 |
| news_facts | `id` PK, `topic_id` FK, `status`, `verified_by/at`, `verification_note` | 검증 기록을 갖춘 사실만 공개 |
| news_sources | `id` PK, `topic_id` FK, 원자료·지문·시연 여부 | 출처 완전성과 변경 여부 확인 |
| news_fact_evidence | `fact_id/source_id` 복합 PK·각 FK | 같은 주제의 사실과 원자료 연결 |
| news_publications | `id` PK, `topic_id/draft_id` FK | 기사로 공개한 이력이 있으면 Fact 자동 공개 제외 |
| news_drafts/claims/reviews | 기존 초안·문장·검토 관계 | 검증 기사 조회·승인 검사를 그대로 사용 |

공개 응답에는 필요한 내용·출처만 담는다. 검증자, 내부 검토 메모, 원자료 구절 전체, 내부 해시·토큰은 보내지 않는다.

| API (브라우저에서는 `/api/news` 접두사 사용) | 처리 |
| --- | --- |
| `GET /public/feed?limit=30` | 새 통합 피드. `kind: facts` 또는 `article`; 최신 30건 |
| `GET /public/facts/{topic_id}` | 현재도 공개 가능한 주제의 검증 Fact 상세 |
| `GET /public`, `/public/{publication_id}` | 기존 기사용 API·형식 유지 |
| `POST /drafts/{draft_id}/verify-and-save` | 사람 확인·기사 승인·공개를 함께 저장하는 간편 경로 |

기사 ID와 Fact 소식의 주제 ID는 서로 다른 테이블의 식별자이므로 `kind`와 `id`를 함께 사용한다. Node 공개 허용 경로를 명시적으로 추가했고 비공개 API의 관리자 세션·쓰기 보호와 FastAPI 내부 토큰 인증은 유지한다.

### SQL 처리

- 이미 뉴스 V8.5.2가 설치된 DB: **이번 수정용 SQL 실행 없음**. 초기화·샘플 재등록·강제 업그레이드를 하지 않는다.
- 신규 설치: [README SQL 처리 순서](../README.md#7-sql-파일-처리-방법)에 따라 기본 SQL 01~04를 설치한다.
- 예약 테이블이 필요한 경우: 기존 SQL 05와 15번 준비 절차를 따른다. 이번 Fact 피드 때문에 SQL 05를 추가로 적용할 필요는 없다.
- 구형 구조의 별도 업그레이드가 필요한 경우: 기존 백업·`--upgrade-existing` 안내를 따른다. 이번 화면 수정과 구별한다.

## 4. 데이터 수집 방법

| 단계 | 유지/변경 | 입력·결과 |
| --- | --- | --- |
| 자료 확인 | 유지 | 사람이 기관 원문을 열어 기관·제목·HTTPS URL·공개 시점(UTC)·필요 구절·이용 조건 기록 |
| 수집 입력 | 유지 | 직접 등록 또는 UTF-8 CSV/JSON 중 하나. 후보 Fact와 근거 연결 저장 |
| 원문 검증 | 화면 간소화 유지 | 원문 대조 확인과 선택 메모로 검증. 빈 메모는 실제 확인 행동을 나타내는 기본 문구로 기록 |
| 메인 열람 | 변경 | 기사 게시 이력이 없는 운영 주제는 검증 Fact만으로 소식 표시 |
| AI 기사 | 선택 경로 | 검증 Fact만 전달, 초안은 비공개, 사람의 원문 비교·검증 저장 필요 |
| 16시 예약 | 기존 코드 유지 | 한국 시간 16:00에 비공개 초안·노션 검토 대기 저장. Fact 검증·기사 공개 자동 수행 안 함 |

자료: [종로 CSV](../data/news/jongno_20261020/jongno_events_20261020.csv) / [같은 JSON](../data/news/jongno_20261020/jongno_events_20261020.json), **Fact 후보 8건·서로 다른 출처 3건**. 가져오기만으로 검증되거나 게시되지 않는다. [직접 입력 예시](NEWS_SOURCES.md)를 따른다. URL 본문 자동 수집은 추가하지 않았다.

## 5. 개발 환경

| 항목 | 기존 구성·이번 적용 |
| --- | --- |
| 웹/세션 | Node.js·Express, 기본 `127.0.0.1:3100` |
| 뉴스 API | Python FastAPI, 기본 `127.0.0.1:8001` |
| DB | MySQL 8.0, 기존 뉴스 구조 유지 |
| AI | 기존 코드 설정 `gpt-6-luna`, 키·실제 API 모델 권한 별도 필요. Fact 열람은 호출 불필요 |
| 의존성 | `package.json`, `news_service/requirements*.txt` 변경 없음 |
| 캐시 | HTML·뉴스 JS/CSS에 no-store, 뉴스 자산 버전 표시 갱신 |
| 설정 | 기존 `.env` 보존. 새 비밀 설정 없음 |
| 검증 환경 | Linux, Node 24.19.0, Python 3.12.14, MySQL 8.0.36, Chromium 134.0.6998.35 |
| Windows 적용 | 기존 서버 둘 다 종료 → 최신 폴더에서 `09_뉴스_서버시작.bat` → 관리자/사용자 Ctrl+F5 |

최신 파일 표시 `data-news-view="verified-facts-v1"`와 실제 제공 HTML을 비교하는 PowerShell 절차는 [적용·미노출 확인](NEWS_PUBLICATION.md#최신-화면을-실행하고-있는지-확인)에 있다. 이 파일 표시가 없거나 이전 지역 버튼이 보이면 최신 코드·실행 폴더·프로세스·브라우저를 구별해 확인한다.

반복 확인: 검증 전 후보 미노출 → Fact 검증 후 표시 → 내용/출처 열람 → 수정 후 제외 → 재검증 후 복귀 → 기사 검증 저장 후 한 카드로 교체 → 공개 중단 후 Fact 재등장 없음. 기사 초안은 최종 검증 전까지 본문이 공개되면 안 된다.

명령·결과·경고는 [검증 기록](../NEWS_TEST_REPORT.md)에 있다. 실제 MySQL 테스트는 별도 `news_test_*` DB를 만들고 제거하며 운영 DB를 사용하지 않는다. 브라우저 검사도 별도 테스트 앱에서만 모의 AI를 허용한다.
