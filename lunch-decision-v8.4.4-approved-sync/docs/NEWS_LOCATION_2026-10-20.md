# 지역 소식 위치별 조회·행사일정 보완 문서

**이후 추가된 현재 검수 방식:** [ChatGPT 참고 검수·사람 네 포인트와 예시](NEWS_AI_REVIEW.md). 아래 단일 확인 화면·검증 수치는 해당 변경 당시 기록이며 현재 화면은 네 포인트를 직접 확인합니다. 새 SQL 없이 적용합니다.

**최신 자료 보완:** [Word 제출본](2차_도메인에_맞는_뉴스_세팅하기_최성환.docx) · [메인·관리자 처리와 기타 변경 내역](DOMAIN_NEWS_SETUP.md). 단일 날짜 `date`뿐 아니라 기존 종로 CSV의 행사 기간 `date_range`도 공개 일정으로 표시하도록 조건을 보완했습니다. 추가 확인 결과 실제 MySQL **104개**·Node **40개**·브라우저 흐름 통과. 아래 103개는 앞선 위치별 조회 변경 당시 기록입니다.


문서·화면 기준: **2026-10-20 / 20261020-location-1**. 기존 1~5 기재 형식을 따른다. 앞선 Fact 공개 변경은 [당시 보고서](NEWS_CHANGE_2026-10-20.md), 현재 설치·진단은 [적용 안내](NEWS_PUBLICATION.md)에 있다.

| 행사 날짜 | 본문에 포함 | 행사일정으로 별도 표시, 검증·게시 날짜와 구별 |
| 이전 화면 | 폴더·서버·캐시가 섞여 적용 확인 어려움 | 19번 실행 파일로 파일·제공 화면·Python 버전 8개 검사 |

## 1. 기능정의서

| 번호 | 기능 | 처리·확인 기준 |
| --- | --- | --- |
| L01 | 위치별 소식 | 메인 상단 국가 → 시/도 → 시군구의 실제 `districts.id`로 검증 Fact·공개 기사를 최신 30건 조회 |
| L02 | 지역 변경 | 상위 선택 해제 시 이전 카드를 비우고 시군구 선택을 안내. 빠른 전환에서 이전 응답을 무시 |
| L03 | 행사일정 | 공개 가능한 날짜 Fact의 시작일·종료일만 표시. 단일 날짜와 기간 지원. 일반 뉴스에는 없는 일정을 만들지 않음 |
| L04 | 기사별 일정 | 기사 제목·본문 문장에 실제 연결된 날짜 Fact만 표시. 같은 주제의 다른 행사는 제외 |
| L05 | 관리자 확인 | 상태 변경 버튼 없음. **이 지역 소식 확인** 링크가 해당 시군구를 메인에 복원 |
| L06 | 적용 진단 | `19_뉴스_화면확인.bat` / `npm run news:doctor`. DB 변경·유료 호출·프로세스 종료 없음 |

위치는 **사용자가 선택한 메인의 시군구**다. GPS는 기존 거리 계산 기능을 유지하고 뉴스 지역으로 자동 변환하지 않는다. 여행 도시 선택도 뉴스 지역을 바꾸지 않는다. 원문 검증·공개 중단·시연 자료 제외 등 기존 공개 조건을 유지한다.

## 2. 화면구성도·설계

| 화면 | 구성·동작 |
| --- | --- |
| 사용자 상단 | 기존 국가·시/도·시군구·동·상권 선택 유지 |
| 지역 소식 헤더 | 지역 소식, 선택한 국가/시도/시군구, 새로고침. 별도 점심·여행 전환 버튼 없음 |
| 소식 카드 | 지역·소식 종류·제목·행사일정(있는 경우)·요약·검증/게시 날짜·소식 읽기 |
| 소식 상세 | 기사/검증 사실, 행사 일정과 관련 설명, 원자료 출처 링크 |
| 관리자 | 수정·근거 연결·원문 대조·삭제, 원문과 기사 비교·확인 하나·검증 완료 저장. 상태 변경 항목 없음 |
| 진단 실행 | 실행 폴더·확인 주소·기대 버전·PASS/FAIL과 재시작 순서 표시. 비밀번호·키는 출력하지 않음 |

`public/script.js`는 화면용 가상 지역 ID를 실제 시군구 PK로 변환한 뒤 `main-region-changed` 이벤트를 보낸다. `public/news-public.js`는 지역이 바뀔 때 이전 요청을 무효화하고 해당 시군구로 조회한다. 상세 조회도 동일한 시군구로 확인하며 다른 지역으로 바꾸면 열린 상세창을 닫는다. 관리자 변경 알림·화면 복귀·보이는 탭의 30초 재조회도 유지한다.

실제 화면: [8단계 실행 GIF](assets/news-publication-demo.gif). 격리 MySQL·모의 AI 응답으로 녹화한 화면이며 운영 기사나 실제 OpenAI 호출이 아니다.

## 3. DB 설계

**테이블·컬럼·인덱스 변경 없음. 추가 SQL 실행·기존 DB 초기화·자료 재입력이 필요 없다.** 기존 SQL 01~05의 설치·업그레이드 절차는 [뉴스 설계 안내](../README_NEWS_V8.5.2.md)를 따른다.

| 기존 데이터 | 이번 사용 |
| --- | --- |
| `news_topics.district_id` → `districts.id` | 선택한 시군구의 소식만 조회 |
| `news_facts.event_start`, `event_end` | 검증 날짜 Fact의 행사일정 |
| `news_facts.status`, 검증자·검증 시각·출처 근거 | 공개 가능한 Fact만 사용 |
| `news_claims` → `news_claim_facts` → `news_facts` | 기사의 실제 문장 근거에 연결된 행사만 사용 |
| `news_publications`, `news_reviews` | 공개·승인·본문/근거 해시 재검사와 공개 중단 유지 |

공개 응답에 `events: [{label, start_date, end_date}]`를 추가한다. 단일 날짜는 종료일을 시작일과 같게 반환한다. 날짜는 지역의 달력 날짜로 표시하며 UTC 게시 시각과 혼동하지 않는다. 기존 API의 다른 필드는 유지한다.

| Node 공개 URL | 기능 |
| --- | --- |
| `GET /api/news/public/feed?district_id=1&limit=30` | 시군구별 검증 Fact·기사 통합 피드 |
| `GET /api/news/public/facts/{topic_id}?district_id=1` | 같은 시군구의 검증 Fact 상세 |
| `GET /api/news/public/{publication_id}?district_id=1` | 같은 시군구의 검증 기사 상세 |
| `GET /api/news/public/version` | 시작 시 읽은 Python 릴리스·화면 버전. DB·AI 호출 없음 |

`district_id=1`은 예시다. 해당 PC의 실제 PK를 사용한다. 공개 읽기도 Node 서버의 내부 토큰 중계를 거치며 브라우저에 토큰을 노출하지 않는다.

## 4. 데이터 수집 방법

원문을 사람이 직접 열어 HTTPS URL·관련 구절·이용 조건을 등록하거나 기존 UTF-8 CSV/JSON으로 가져온다. 날짜 Fact는 `fact_type=date` 또는 `date_range`와 `event_start`, 필요하면 `event_end`를 입력하고 근거를 연결한다. **원문 대조 → Fact 검증 완료** 후 해당 지역에 표시한다. 기사로 공개한 이력이 있는 주제는 기사 재검증·저장으로 다시 공개한다.

새 크롤러·날짜 추정·자동 사실 판정을 추가하지 않았다. `gpt-6-luna`는 기존의 선택적 초안 생성 경로에서만 사용한다. 16시 예약은 등록·검증한 Fact의 비공개 초안과 노션 전송을 유지하며 검증·게시를 자동으로 하지 않는다.

## 5. 개발 환경·실행·테스트

기존 Node.js·Python FastAPI·MySQL 구성을 유지한다. 이번 검증 환경은 Linux, Node.js 24.19.0, Python 3.12, MySQL 8.0.36, Chromium 134다.

기존 설치 폴더에 최신 파일 적용 후:

```powershell
# 기존 Node·FastAPI 창 각각 Ctrl+C로 종료한 다음, package.json이 있는 폴더에서 실행합니다.
.\09_뉴스_서버시작.bat
# 새 PowerShell 창에서 같은 폴더로 이동하여 실행합니다.
.\19_뉴스_화면확인.bat
```

진단 8개 PASS 후 사용자·관리자 탭에서 **Ctrl+F5**를 누른다. 서버 두 창은 유지한다. 기본 주소는 `http://127.0.0.1:3100/`, 관리자는 `/admin`이다. 설치 폴더와 제공 중인 화면 버전이 다르면 [복구 순서](NEWS_PUBLICATION.md#최신-업데이트-적용-순서)를 따른다.

| 실행한 검사 | 결과·범위 |
| --- | --- |
| 실제 MySQL 뉴스 전체 | **103개 통과**. 기존 98개 + 행사일정/기사 근거/지역별 상세/버전 5개 |
| `npm run test:ui` | **40개 통과**. 기존 36개 + 화면 진단 4개 |
| 실제 Node·FastAPI·MySQL·Chromium | 한국·일본 지역 전환, 상위 해제, 늦은 이전 응답 무시, 행사일정·출처, 관리자 링크, 상태 변경 미노출, 390px 모바일 통과 |
| 실행 진단 | 실제 서버에서 파일/HTTP/Python 버전 8개 PASS |
| JS 구문·README 자동 생성 | `npm run check`, `npm run docs:news:check` 통과 |

재확인할 항목: 선택 지역만 조회, 상위 선택 해제 시 카드 제거, 빠른 시군구 전환, 단일/기간 일정, 검증 전 날짜 제외, 기사에 사용하지 않은 일정 제외, 날짜 없는 일반 뉴스, Fact 수정 시 제외·재검증 반영, 기사 교체·공개 중단, 이전 JS/서버 진단, 모바일 배치.

```powershell
npm run test:ui
npm run check
npm run docs:news:check
.\.venv\Scripts\python.exe -m pytest tests/news -q
```

마지막 명령은 기본적으로 SQLite 기반 무료 검사이며, 실제 MySQL 검사는 별도의 `news_test_*` DB를 사용하는 기존 통합 절차로 실행한다. 위 MySQL 결과는 그 격리 환경에서 직접 확인한 결과다. 실제 OpenAI 유료 호출·노션 API·사용자 운영 DB·Windows BAT/작업 스케줄러는 실행하지 않았다.
