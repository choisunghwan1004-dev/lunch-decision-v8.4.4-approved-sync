# 검증 저장한 뉴스가 지역 소식에 보이지 않을 때

현재 기본 화면은 [간편 원문 비교·검증 저장](NEWS_SIMPLE_REVIEW.md)을 사용한다. **원문 비교 → 확인 체크 1개 → 검증 완료·저장**으로 검토·승인·공개를 함께 저장한다. 메모는 선택이다. 이전의 별도 최종 승인·승인본 게시·상태 변경 화면은 제거했다.

1. 최신 코드를 적용한 뒤 기존 Node·FastAPI 창을 종료하고 `09_뉴스_서버시작.bat`으로 시작한다. 관리자·사용자 모두 **Ctrl+F5**로 최신 화면을 읽는다. 추가 SQL·DB 초기화는 필요 없다.
2. 관리자 지역 뉴스에서 해당 주제를 고르고 **메인 노출 상태**의 `검증 저장` 건수를 확인한다.
3. 저장된 기사를 **원문 비교·검증**으로 열고 원문 대조 체크 후 **검증 완료·저장**을 누른다. 메모가 비어 있어도 저장된다. 체크 없이 누르면 한글 안내를 표시한다.
4. 메인 **지역 소식**에서 확인한다. 점심·여행 지역 전환은 없고 검증 저장된 기사 최대 30건을 바로 표시한다. 다른 창에서 이미 열어 두었다면 저장 알림·화면 복귀 또는 새로고침으로 다시 읽는다.

| 현재 자료 | 의미·처리 |
| --- | --- |
| 출처·Fact만 있고 기사 0건 | 아직 기사가 없다. 검증 Fact로 초안을 만든 뒤 원문을 비교해 검증 저장한다. 실제 OpenAI 호출은 키·모델 권한·비용 확인이 필요하다. |
| 기사는 있으나 검증 저장 0건 | 초안 또는 이전 승인 상태다. 원문 비교·검증에서 확인 후 한 번에 저장한다. |
| 검증 저장 1건 이상 | 공개 저장 상태다. 지역 소식 새로고침으로 확인한다. |
| 시연 자료·근거 변경·불일치 문장 | 운영 공개 제한 또는 재검증이 필요하다. 실제 근거·내용 수정본으로 확인한다. |
| 저장 중 오류 | 검토·승인·공개 전체를 함께 취소한다. 오류 안내를 확인하고 다시 진행하며 DB를 초기화하지 않는다. |

첨부됐던 `String should have at least 3 characters`와 `Input should be True`는 이전 필수 의견·확인 체크 누락 오류였다. 현재 기본 화면에서 그 항목들을 반복 입력할 필요는 없다. 입력 오류는 저장 전에 거절된 것이며 기존 자료 유실을 뜻하지 않는다.

현재 기사·근거가 열어 본 내용과 달라지면 저장을 거절하고 새로 확인하도록 한다. 사용자 운영 DB를 직접 보지 않고 개별 저장 상태를 단정하지 않는다. [연결 복구](../README_NEWS_RECOVERY.md), [간편 검증 상세](NEWS_SIMPLE_REVIEW.md)를 함께 참고한다.
