# 검증한 Fact·뉴스가 지역 소식에 보이지 않을 때

## 추가·변경 내용 (2026-10-20)

| 변경 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 조회 조건 | 최종 게시 기사만 메인에 표시 | 검증 Fact와 기사 통합 피드, 같은 주제 한 카드 |
| 적용·확인 | 재시작·새로고침 안내 | 파일/서버 HTML/피드별 PowerShell 진단, 두 서버 재시작, 추가 SQL 없음 |

기능·화면·DB·수집·환경의 통합 기재와 실제 검증 결과는 [추가·변경 보고서](NEWS_CHANGE_2026-10-20.md)를 참고하세요.

현재 메인은 **지역 소식** 제목과 **새로고침**만 표시한다. 오른쪽 **점심 지역·여행 지역** 버튼과 **점심과 여행, 지역 소식** 제목은 이전 화면이다. 첨부 화면이 이전 UI라는 것은 확인할 수 있으나, 사용자 PC의 파일·실행 프로세스·브라우저 중 어느 곳이 이전 버전인지는 아래 확인이 필요하다.

기존 조회는 `news_publications`에 최종 저장된 기사만 읽었다. 따라서 **Fact 검증 완료만 한 자료는 메인에 나오지 않았다.** 새 화면은 `GET /api/news/public/feed?limit=30`으로 검증된 Fact 소식과 검증·저장 기사를 함께 읽는다. 점심·여행 지역으로 필터링하지 않는다. Fact 공개 조회는 OpenAI를 호출하지 않는다.

## 자료에 따른 표시

| 현재 자료 | 지역 소식 표시·처리 |
| --- | --- |
| 출처·Fact 후보만 저장 | 아직 표시하지 않는다. Fact의 **근거 연결 → 원문 대조 → Fact 검증 완료**를 진행한다. 메모는 선택이다. |
| 운영 주제에서 Fact 검증 완료, 기사 게시 이력 없음 | **원문 검증 소식**으로 즉시 표시한다. 같은 주제의 검증 Fact를 한 카드로 묶고 상세에서 내용·출처를 보여준다. AI 생성 불필요. |
| 위 주제에서 AI 초안 생성 | 검증 Fact 소식은 유지하고 미검토 AI 기사 본문은 공개하지 않는다. |
| 원문과 기사 비교 후 확인 한 개 → 검증 완료·저장 | 같은 주제의 Fact 카드를 **검증 기사**로 교체한다. 메모 없이 저장 가능. |
| 기사를 공개 중단하거나 근거를 바꿔 게시 해제 | 해당 기사는 빠진다. Fact 카드로 자동 재등장하지 않는다. 기사 게시 이력이 있는 주제는 기사 재검증·저장으로만 다시 공개한다. |
| Fact 내용·출처·근거 연결 변경 | 영향받은 Fact는 검증 대기로 돌아가 공개 대상에서 빠진다. 해당 주제의 다른 검증 Fact는 남을 수 있다. 관련 기사 승인은 해제된다. |
| 시연용 주제·시연 출처·불완전 출처·검증자/시각 없는 Fact | 운영 화면에 표시하지 않는다. 실제 원문·근거를 갖춘 운영 자료를 검증한다. |

자료를 고치려면 기존의 **수정·근거 연결·원문 대조·삭제**를 사용한다. 별도 상태 변경 항목은 없다. 자료를 실제 원문과 비교하는 작업은 사람이 수행한다. 원문 URL을 자동 수집하거나 AI가 진위를 판정하는 기능은 추가하지 않았다.

## 최신 화면을 실행하고 있는지 확인

### 1. 실행할 폴더의 파일 확인

탐색기에서 **package.json, server.js, news_service, 09_뉴스_서버시작.bat**이 함께 있는 폴더를 연다. 그 주소창에 `powershell`을 입력한 뒤 아래를 실행한다.

```powershell
Test-Path .\server.js
Select-String -Path .\public\index.html -SimpleMatch 'data-news-view="verified-facts-v1"'
Select-String -Path .\news_service\app.py -SimpleMatch "@app.get('/public/feed'"
```

첫 결과는 `True`, 아래 두 명령은 해당 줄을 보여야 한다. 줄이 나오지 않으면 내려받은 코드가 이전 버전이다. [main 최신 ZIP](https://github.com/choisunghwan1004-dev/lunch-decision-v8.4.4-approved-sync/archive/refs/heads/main.zip)을 새 폴더에 완전히 풀고 기존 `.env`를 복사한다. `.env.example`로 기존 설정을 덮어쓰지 않는다. 새 폴더에서는 `.venv`도 새로 준비해야 하므로 [Windows 실행 안내](../README_AUTOMATION.md)를 따른다. Git으로 설치한 폴더는 자신의 변경을 보존하면서 최신 main을 반영한다.

**이 수정은 SQL 추가·DB 초기화가 필요 없다. 기존 자료를 다시 입력하지 않는다.** 기존 검증 Fact도 공개 조건이 맞으면 바로 조회한다.

### 2. Node·FastAPI 모두 다시 시작

기존 서버 창에서 각각 **Ctrl+C**로 종료한다. 최신 파일을 확인한 같은 폴더에서 실행한다.

```powershell
.\09_뉴스_서버시작.bat
```

Node만 재시작하면 Python의 새 Fact 조회 경로가 반영되지 않는다. `EADDRINUSE`가 나오면 실행 중인 이전 서버 창을 확인한다. 이전에 보았던 PID는 이미 바뀔 수 있으므로 그대로 종료 명령에 재사용하지 않는다. [포트·연결 복구 안내](../README_NEWS_RECOVERY.md)를 참고한다.

### 3. 서버가 실제 제공하는 HTML·조회 결과 확인

기본 PORT 3100을 사용하는 경우다. 다른 PORT를 설정했으면 아래 주소를 바꾼다.

```powershell
$page = Invoke-WebRequest -UseBasicParsing 'http://127.0.0.1:3100/'
$page.Content -match 'data-news-view="verified-facts-v1"'
Invoke-RestMethod 'http://127.0.0.1:3100/api/news/public/feed?limit=30'
```

| 결과 | 다음 행동 |
| --- | --- |
| HTML 검사 `False` | 다른 폴더의 서버나 이전 프로세스를 실행 중이다. 최신 폴더·3100 포트의 실행 서버를 확인한다. |
| HTML `True`, 브라우저에는 이전 제목·버튼 | 사용자·관리자 탭에서 **Ctrl+F5**. 그래도 다르면 주소의 PORT를 확인한다. |
| 피드 404·422 | Node 또는 FastAPI가 이전 버전일 수 있다. 두 서버 모두 최신 폴더에서 다시 시작한다. |
| 피드 503·연결/DB 안내 | [뉴스 연결 복구](../README_NEWS_RECOVERY.md). 오류를 빈 목록이나 저장 실패로 간주하지 않는다. |
| 피드가 빈 배열 | 위 표시 조건을 확인한다. 시연 여부·검증 완료·출처·기존 기사 중단 이력에 따라 실제 공개 대상이 없을 수 있다. |
| 피드에 `kind: facts` 또는 `article` 있음 | 서버 조회는 정상. `http://127.0.0.1:3100/#regionalNews`에서 새로고침한다. |

새 Node는 HTML과 뉴스 JS/CSS에 `Cache-Control: no-store`를 보낸다. 관리자 변경 알림·화면 복귀·새로고침과 화면이 보이는 동안 30초 재조회로 메인을 갱신한다. 이미 캐시된 이전 HTML은 첫 적용 시 Ctrl+F5로 읽는다.

## 테스트할 항목

1. 운영용 주제에 출처·Fact·근거를 저장한다. 검증 전 메인에는 나오지 않아야 한다.
2. Fact의 원문 대조를 확인하고 검증 완료한다. **AI 생성 없이** 열린 메인에 내용·출처가 나타나야 한다.
3. 같은 주제의 다른 Fact는 검증된 항목만 함께 표시되어야 한다. 시연용 자료는 제외되어야 한다.
4. Fact를 수정하면 후보로 돌아가 해당 내용이 빠지고, 재검증 후 다시 보여야 한다.
5. 선택적으로 AI 기사를 만들고 원문 비교·확인 한 개·검증 완료·저장을 진행한다. 같은 주제가 한 개의 기사 카드로 바뀌어야 한다.
6. 기사 공개 중단 후 Fact 카드로 다시 나타나지 않아야 한다. 재공개는 기사 검증·저장으로 진행한다.
7. 점심·여행 지역을 바꿔도 뉴스가 유지되고, 모바일에서 본문·출처를 읽을 수 있어야 한다.

자동 검사는 [Fact 피드 테스트](../tests/news/test_public_facts.py), [기사 저장 테스트](../tests/news/test_simple_review.py), [실제 DB·브라우저 통합 검사](../tests/news/browser_smoke.py)를 사용한다. 사용자 PC의 실제 DB 상태를 직접 확인한 결과는 아니다.
